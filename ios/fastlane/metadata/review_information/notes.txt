ompanion is a client for omp, an AI coding agent that runs on the user's own machines. The app has no account of its own: to reach every screen, add the demo machine we run for this review.

1. In the sidebar, tap Add machine. Enter Name: Demo, Host: <HOST>, Port: 22222, User: review, Authentication: Password, Password: <PASSWORD>. Tap Save.
2. The machine's page opens. Under System, tap Connect. The app asks "Trust this host?" the first time; tap Trust. The demo machine is a container we run only during this review and destroy afterwards; it holds no personal data.
3. The System section then shows omp version 18.3.1 and Companion: Uploaded.
4. Go back to the list of machines, tap the ⋮ on the machine's row and choose New session. Set Working directory to ~/work/notes-api and tap Start.
5. Type any message in the composer and send it. The demo machine's model is an offline demo model that answers with canned replies (markdown, a shell command, a file read and edit, a todo list, reasoning, a question, then a long streamed answer). It makes no request to any AI provider and costs nothing.

Everything else works on the same machine: the Files panel edits files and shows git diffs, the Terminal opens a shell, and Configure browses omp's settings, model roles, MCP servers, plugins and skills. Usage has no limits to show on the demo machine. No account, purchase or external service is needed to reach any of it. App Review may also connect to its own machine with omp 18.3.1 installed.

Why the app needs a server (guidelines 2.1 and 4.2)

ompanion is a client for a machine the user owns, like an SSH client: without a machine there is nothing to do in it. The demo host has the agent pre-installed and an offline demo model, so every feature can be tested without a server or AI costs. If it is unreachable during review, send us a note and we will bring it back within a day.

About guideline 2.5.2

The app never runs downloaded code on the device, and no download changes its features. At the user's request it installs omp, an open-source binary, on the user's own remote machine over SSH, as an SSH client runs commands on a server. The machine downloads the release itself with curl or wget (PowerShell on Windows); only without them does the app stream the release from github.com to the machine over SFTP, never running or keeping it on the device, and the machine checks its SHA-256 against the value pinned in the app. The app also uploads a small JavaScript extension (about 60 KB, built from the same public repository) that the user's own omp loads on that machine; it runs there, not on the device or on any server of ours.

About guideline 5.1.2(i)

The app shares no user data with any third party or AI provider chosen by us. Prompts go over SSH to omp on the user's own machine, which calls the AI provider the user configured there, with the user's own credentials. A key the user types into the app goes over SSH to omp and is not kept on the device; OAuth sign-in pages open in the user's browser, and the token stays on the user's machine. The app has no analytics, crash reporting, advertising or tracking.

About AI-generated content

The chat shows replies from the user's own agent and providers. The app adds no moderation of its own because it is a remote control, not a publisher: nothing in the chat is shared with other users or with us, and there is no feed, no public profile and no messaging between users.
